# 賞味期限管理アプリ

食品の開封日と保存日数から賞味期限を自動計算し、期限の状態を管理するWebアプリです。

## 開発背景

アルバイト先では、食品の開封後の期限を手書きで管理していました。

開封日と保存日数から期限を計算する必要があり、手作業では計算ミスが発生する可能性がありました。

そこで、期限計算を自動化し、誰が作業しても同じルールで期限を管理できるようにすることを目的として、このアプリを開発しました。

## 主な機能

- 食品名・開封日・保存日数の登録
- 開封日と保存日数から賞味期限を自動計算
- 登録した食品の一覧表示
- 食品名・賞味期限の編集
- 登録した食品の削除
- 賞味期限に応じた状態判定
- 期限切れ・期限間近の食品を通知対象として抽出
- 不正な入力値に対するバリデーション

## 期限状態の判定ルール

現在の日付と賞味期限を比較し、以下の3段階で状態を判定します。

| 状態 | 条件 |
| --- | --- |
| 期限切れ | 賞味期限が今日より前 |
| 期限間近 | 賞味期限が今日から3日以内 |
| 通常 | 賞味期限まで4日以上 |

不正な日付データについては「日付エラー」として扱います。

## 工夫した点

### 1. 期限判定ロジックを分離

期限状態の判定を `determine_expiry_status()` として分離しました。

Web画面の処理と期限判定のルールを分けることで、判定ロジック単体でテストしやすい構成にしています。

### 2. 変更される可能性のある値を定数化

期限間近と判定する日数を、

```python
EXPIRING_SOON_DAYS = 3
```

として定数化しています。

現在は3日としていますが、今後ルールを変更する場合でも、変更箇所を分かりやすくしています。

### 3. 境界値を意識したテスト

pytestを使用して、期限判定や入力値検証をテストしています。

例えば期限判定では、

- 昨日 → 期限切れ
- 今日 → 期限間近
- 3日後 → 期限間近
- 4日後 → 通常

となることをテストしています。

また、存在しない日付、不正な保存日数、非常に大きな値などを入力しても、アプリケーションが予期せずエラー終了しないことを確認しています。

### 4. テスト用データベースの分離

pytestでは一時的なSQLiteデータベースを作成し、本番用のデータベースとは分けてテストしています。

これにより、テスト実行によって通常使用するデータが変更されないようにしています。

## 今後の改善点

### 期限間近の日数を利用者が設定できるようにする

現在は「3日以内」を期限間近としています。

この値は開発時に固定値として設定しましたが、実際の店舗運用では従業員へのヒアリングを行い、業務に適した日数を決定する必要があると考えています。

将来的には、店舗や利用者ごとに期限間近と判定する日数を設定できるようにしたいです。

### 通知機能との連携

現在は、期限切れ・期限間近の食品を通知対象として抽出するロジックまで実装しています。

今後は、この処理をメールなどの通知機能と連携させることで、期限が近づいた食品を自動的に知らせられるようにしたいです。

### UIの改善

現在は機能実装を優先したシンプルな画面のため、期限状態を視覚的に判別しやすくするなど、操作性を改善したいと考えています。

## 起動方法

### 1. リポジトリを取得

```bash
git clone https://github.com/sawasawa003838-max/kigenkanri-flask.git
cd kigenkanri-flask
```

### 2. 必要なライブラリをインストール

```bash
pip install -r requirements.txt
```

### 3. アプリケーションを起動

```bash
python app.py
```

### 4. ブラウザでアクセス

```text
http://127.0.0.1:5000
```

`database.db` はGit管理していません。

`python app.py` でアプリケーションを起動すると `init_db()` が実行され、初回起動時に `foods` テーブルが作成されます。
